# Mimoru 2.5.0 RC1

Коммерческая платформа управления Telegram-сообществами на русском языке. Один экземпляр обслуживает несколько независимых групп. Управление работает внутри Telegram: русскими командами и кнопочной панелью, без сайта и Mini App.

## Что реализовано

### Панель владельца группы

- «Мои группы» и отдельная карточка каждой подключённой группы;
- статистика выбранной группы и участников;
- настройки защиты, автоматизации и приветствия;
- запрещённые слова и обязательные каналы;
- роли и ранги администраторов;
- журнал модерации;
- тариф, срок подписки и лимиты;
- рекламная площадка группы и список заказов.

### Панель владельца сервиса

Доступна Telegram ID из `SERVICE_OWNER_IDS`:

- владельцы подключённых групп и их группы;
- заблокированные пользователи;
- платежи и Telegram Stars;
- рекламные площадки и заказы;
- обращения поддержки;
- общая статистика сервиса;
- ручная выдача тарифов, промокоды, блокировки и рассылка.

### Модерация и защита

- бан, разбан, мут, размут и предупреждения;
- временные наказания и журнал;
- антифлуд, повторы, ссылки, запрещённые слова и капс;
- ограничения голосовых, стикеров и пересылок;
- капча, карантин новичков и обязательная подписка;
- антирейд, ночной режим и локдаун;
- фильтр массовых упоминаний, координированного спама и сообщений от имени каналов;
- проверка отредактированных сообщений;
- жалобы, автоответы и запланированные публикации.

### Тарифы и подписки

- Free, Standard и Pro;
- пробный период;
- покупка Standard/Pro через Telegram Stars;
- ручная выдача доступа владельцем сервиса;
- промокоды;
- отдельный тариф и срок для каждой группы.

### Рекламный модуль

Владелец группы создаёт площадку командой:

```text
реклама площадка 250 | Описание аудитории, формата и условий
```

Рекламодатель открывает «Купить рекламу», выбирает площадку и создаёт заявку:

```text
заказать рекламу ID_ПЛОЩАДКИ | Текст рекламной публикации
```

Владелец площадки управляет заказом командами принятия, отклонения и публикации. Платёжные операции проходят через текущую схему Telegram Stars и встроенные проверки целостности.

## Подключение группы

Потребуются Docker и Docker Compose. Создайте `.env` из примера и заполните как минимум:

```bash
cp .env.example .env
```

```env
BOT_TOKEN=токен_от_BotFather
SERVICE_OWNER_IDS=ваш_telegram_id
POSTGRES_PASSWORD=сложный_пароль
DATABASE_URL=postgresql+asyncpg://moderator:сложный_пароль@postgres:5432/moderator
REDIS_URL=redis://redis:6379/0
```

Запуск:

```bash
docker compose up --build -d
docker compose logs -f bot
```

Миграции Alembic применяются автоматически.

Для подключения группы:

1. Отключите Privacy Mode в BotFather.
2. Добавьте Mimoru в группу.
3. Нажмите кнопку «🛡 Назначить администратором» и выдайте предложенные права, включая управление чатом, удаление сообщений, ограничения участников, приглашения, закрепление сообщений и назначение администраторов.
4. После получения прав Mimoru пришлёт следующий шаг. Нажмите «📋 подключить», вставьте скопированное слово в группу и отправьте его от имени владельца группы.
5. Дальнейшая настройка продолжается в личном диалоге с Mimoru.

## Модерация

Для `пред`, `мут` и `бан` причина, если она вводится текстом, указывается **со второй строки**.

Ответом на сообщение пользователя:

```text
пред
Спам
```

```text
мут 2ч
Флуд
```

```text
бан
Повторное нарушение
```

Если причина второй строкой не указана и в настройках разрешён режим кнопок, Mimoru предложит выбрать причину кнопками. Для мута поддерживаются, в частности, формы `1м`, `1 мин` и `1 минуту`.

Полный перечень команд находится в `COMMANDS_RU.md`.

## Проверка проекта

Основной локальный и CI-runner один:

```bash
./scripts/check.sh
```

Он включает компиляцию, Ruff-проверки, pytest, аудит миграций и схемы, проверку регистрации роутеров, безопасности, навигации, callback-кнопок, FSM, deployment consistency и целостности кодовой базы.

`check.sh` намеренно работает без базы данных, поэтому быстрый прогон возможен в любом окружении. Проверки, которые нельзя выполнить на моках — реальное применение цепочки миграций, сверка живой схемы с ORM, уникальные ограничения, защищающие от повторного списания, и `FOR UPDATE` / `SKIP LOCKED`, — вынесены в отдельный скрипт и выполняются в CI на живом PostgreSQL:

```bash
./scripts/check_db.sh
```

Скрипту нужны те же переменные окружения, что и деплою, — `DATABASE_URL`, `REDIS_URL`, `BOT_TOKEN` (см. `.env.example`). Значение `BOT_TOKEN` должно быть в формате `<numeric_bot_id>:<secret>`, иначе конфигурация его отклонит. Тесты с маркером `db` запускаются только этим скриптом. Он никогда не пропускает их молча: без доступной базы он завершается с ошибкой.

## Деплой

На настроенном сервере обновление выполняется через:

```bash
bash /root/Mimoru/scripts/deploy.sh
```

Скрипт получает изменения, проверяет Docker Compose, поднимает PostgreSQL/Redis, собирает новый образ бота, выполняет миграции и preflight, перезапускает сервисы и показывает последние логи.

## Статус

Версия проекта определяется файлом `VERSION`. Перед обновлением production-сервера изменения должны пройти GitHub Actions CI. Реальные Telegram-сценарии, зависящие от прав группы и поведения клиента Telegram, дополнительно проверяются в тестовой группе после деплоя.
